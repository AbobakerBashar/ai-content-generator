For an AI Content Generator SaaS, your header (navigation bar) is going to look different depending on whether the user is just visiting your landing page or is actively logged into the app.

Because you are managing API costs, the most critical element of the logged-in header is visibility of the user's credit balance.

Here is the ideal breakdown for both states:

1. The "Logged Out" Header (The Landing Page)
   The goal here is purely conversion—getting them to sign up or try the tool.

Left Side (Brand Identity):

A clean, text-based logo (e.g., ⚡️ AI Writer).

Note: Keep it clickable so it always routes back to /.

Center (Discovery):

Features: Anchor link to your feature section.

Pricing: Crucial for SaaS. Users want to know what it costs before they commit.

Examples/Wall of Love: A link showing actual content generated by your tool.

Right Side (Conversion Actions):

Sign In: A subtle text link (text-slate-400 hover:text-white).

Get Started: A high-contrast, primary button that routes to your Supabase Auth sign-up page.

2. The "Logged In" Header (The App Dashboard)
   Once they are inside, the header shifts from marketing to utility. This is where you leverage Supabase Auth state.

Left Side (Navigation):

Logo (routes to /dashboard).

New Generation: A quick link or button to start a fresh prompt.

My History / Vault: A link to view past generations saved in the database.

Center (Optional Context):

Sometimes left blank to keep the interface clean, or used for a breadcrumb trail (e.g., Dashboard > Blog Post > Draft).

Right Side (Account & Usage):

The Credit Counter: This is mandatory for AI tools. A small badge displaying remaining tokens/credits (e.g., 💎 42 Credits). It should change color (to yellow or red) when they are running low, with a prompt to "Upgrade."

User Avatar/Dropdown: \* Clicking their avatar opens a menu with:

- Billing/Plan: Route to manage their Stripe subscription.
- API Keys: (If you are exposing your tool via API).
- Sign Out: Triggers the Supabase signOut() method.

Pro-Tip for Next.js Implementation
If you are using the Next.js App Router, you can handle the header logic beautifully using a Server Component.

You can check the Supabase session directly on the server before the page even renders. If a session exists, render the <DashboardHeader /> component (fetching their credit balance from the database); if not, render the <MarketingHeader />. This prevents that awkward UI flicker where the user briefly sees the "Sign In" button before the app realizes they are already logged in.
